# NovaGrid — Архитектура и технологии

Версия: 1.0 (на согласование) · Дата: 2026-10-06

---

## 1. Главное решение: веб-приложение PWA

**NovaGrid — одно веб-приложение (PWA), устанавливаемое на любую платформу.**

| Критерий | PWA (выбрано) | Electron/Tauri | Нативно (Swift/Kotlin) | Flutter |
|---|---|---|---|---|
| Все ОС и устройства одним кодом | ✅ включая iPhone/Android | ⚠️ только десктоп | ❌ 5 кодовых баз | ⚠️ веб всё равно нужен |
| Установка без магазинов | ✅ из браузера | ✅ | ❌ | частично |
| Офлайн | ✅ service worker | ✅ | ✅ | ✅ |
| Размер/простота поставки | ✅ ссылка | ⚠️ сборки под ОС | ❌ | ⚠️ |
| Обновления | ✅ мгновенно у всех | ⚠️ | ❌ ревью магазинов | ⚠️ |

PWA закрывает требование «работать на всех типах устройств и ОС» одной кодовой базой и без
сборочно-магазинной механики. **Позже**, тем же кодом, при желании добавляются обёртки
(Tauri — «настоящий» .exe/.dmg; Capacitor — магазины приложений) — это Этап 7, не v1.

**Ограничения PWA, которые учитываем:** Safari iOS — хранилище ~1 ГБ и может чиститься
(митигация: автосохранение сессии + напоминание «сохранить файл на диск»); нет File System
Access API вне Chromium — на Firefox/Safari/iOS сохранение через скачивание файла (описано в Ф1).

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Язык | **TypeScript** (strict) | типы в модели данных и формулах — надёжность |
| Сборка | **Vite** | скорость, PWA-плагин, воркеры из коробки |
| UI | **React 18** | экосистема, кандидаты грида под React, привычность |
| Состояние | **Zustand** (+собственный delta-стек undo в core/history) | лёгкий, без бойлерплейта; delta-стек вместо zundo — снимки состояния на листе 100k ячеек дороги памятью (решение спайка Этапа 1, SPIKE-1-GRID §2) |
| Стили | собственный CSS на дизайн-токенах | дизайн уникальный и простой — UI-кит не нужен |
| Иконки | lucide (ISC) | тонкий единый стиль |
| Тесты | **Vitest** (unit) + **Playwright** (e2e) | формулы/модель — юнитами, сценарии ТЗ — e2e |
| CI | GitHub Actions: lint + typecheck + test + build | качество на каждый пуш |

## 3. Грид (сердце интерфейса)

Требования к гриду: виртуализация (рендер только видимых ячеек), 60 fps на 100k строк,
полная кастомизация жестов (ПКМ-фильтр, Alt-выделение, Ctrl-массивы), лицензионная чистота.

Рассмотренные варианты:

| Библиотека | Лицензия | Почему не берём сразу |
|---|---|---|
| Handsontable | коммерческая | платная для продукта |
| AG Grid | MIT/Enterprise | контекстные меню, tool panel и ключевые нам фичи — в платной tier |
| Univer / Luckysheet | Apache-2.0 / не поддерживается | тяжёлый «всё-в-одном», противоречит простоте |
| RevoGrid | MIT | хорош, но меньше возможностей тонкой настройки выделений |
| **Glide Data Grid** | **MIT** | быстрый канвас-грид — **кандидат №1 как «не писать своё»** |
| **Собственный канвас-грид** | — | полный контроль над «революционным UX»; риск — время |

**План:** Этап 1 начинается со **спайка 3–5 дней**: минимальный свой canvas-grid против Glide Data Grid.
Критерии выбора: 60 fps @ 100k×30, кастомные ПКМ/Alt/Ctrl-жесты, кириллица/IME-ввод,
размер бандла, трудоёмкость доработки. Решение фиксируется в карте создания.

> **Решение спайка (КТ-2, 2026-10-08): собственный canvas-грид.** Решающий аргумент —
> Ctrl-несмежные массивы (Ф5) не вписываются в модель выделения Glide Data Grid без форка.
> Реализация: `grid/geometry` (виртуализация, юнит-тесты), `grid/renderer` (кадр канваса —
> только видимое окно), `grid/GridCanvas` (жесты, клавиатура, DOM-редактор для IME).
> Полный протокол с критериями и замерами: [SPIKE-1-GRID.md](SPIKE-1-GRID.md).

## 4. Работа с файлами (xls/xlsx/csv)

Комбинация двух проверенных библиотек — закрывает и старые .xls, и стили в .xlsx:

| Задача | Инструмент | Лицензия |
|---|---|---|
| Чтение `.xlsx`/`.xlsm` (значения, формулы, **стили**) | **ExcelJS** | MIT |
| Чтение `.xls` (BIFF8 и старше) | **SheetJS CE** | Apache-2.0 |
| Чтение/запись `.csv`/`.tsv` (разделители, кодировки) | SheetJS CE + свой детектор | Apache-2.0 |
| Запись `.xlsx` со стилями | **ExcelJS** | MIT |

- Парсинг выполняется в **Web Worker** — интерфейс не замирает, показывается прогресс.
- Запись в старый `.xls` не гарантируется: предлагаем «Сохранить как .xlsx» (вопрос №4 в CONCEPT.md).
- Внутреннее представление книги — собственная компактная структура (колоночные массивы,
  типизированные значения) — быстро для грида и мала для IndexedDB.

**Формулы:** читаем и кэш значений, и текст формулы. Показ — значение; в строке формул — формула.
Пересчёт — собственным движком для поддерживаемых функций (список в CONCEPT.md Ф6);
неподдерживаемые помечаются индикатором «не пересчитывается» и сохраняются без изменений.

## 5. Хранение

- **IndexedDB (Dexie, MIT):** рабочие сессии (автосохранение каждые N правок/30 с),
  список недавних файлов (имя, размер, дата, миниатюра), настройки.
- **Файлы пользователя:** напрямую через File System Access API (Chromium-десктоп:
  Ctrl+S пишет в открытый файл), на остальных платформах — скачивание.
- Никаких серверов и облачных хранилищ в v1.

## 6. Структура репозитория

```
src/
  core/       # модель книги: ячейки, листы, выделение, фильтры, undo — чистый TS, без DOM
  formula/    # парсер и вычислитель формул — чистый TS, 100% юнит-покрытие логики
  grid/       # канвас-грид: рендер, виртуализация, жесты (или адаптер Glide Data Grid)
  io/         # чтение/запись файлов + воркеры (ExcelJS/SheetJS изолированы здесь)
  storage/    # Dexie: сессии, недавние, настройки
  ui/         # React: тулбар, поиск, чипы фильтров, статус-бар, панель помощи
  i18n/       # ru/en словари
  app/        # точка входа, PWA, роутинг одного экрана
tests/        # Playwright e2e (сценарии из CONCEPT.md)
```

Правило зависимостей: `core`, `formula` не знают про DOM и React — тестируются юнитами напрямую;
`ui` и `grid` — тонкие слои над ними. Это позволяет менять гридер (свой ↔ Glide) не трогая логику.

## 7. Обновление и релизы

- Публикация: GitHub Pages (авто-деплой из Actions при теге).
- Service worker (Workbox через vite-plugin-pwa): precache оболочки; обновление — «доступна
  новая версия, обновить?» без потери открытой книги (сессия в IndexedDB).
- Демо-файлы для проверки: `tests/fixtures/` — книга из сценария ТЗ (фамилии + суммы), большой файл 100k строк.

## 8. Качество и риски реализации

- Юнит-тесты `core`/`formula`/`io` — цель покрытия ≥ 80%; e2e-сценарии: «открыл → ПКМ-фильтр
  по двум колонкам → Σ», «поиск по всем листам», «сохранил и переоткрыл без потерь».
- Матрица ручной проверки платформ (Windows/macOS/Linux/Android/iOS) — чек-лист в карте создания.
- Ключевые технические риски и митигции — сводная таблица в ROADMAP.md.

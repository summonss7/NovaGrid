# Спайк Этапа 1 — выбор грида и механики быстрой суммы

Дата: 2026-10-08 · Карточка: novagrid-005 · Статус: **решения зафиксированы (КТ-2)**

Спайк по плану CREATION-MAP §2 (1.1 и 1.6): сравнение собственного canvas-грида
с Glide Data Grid и проверка Alt-жеста для мгновенной суммы. Критерии и ход — ниже.

---

## 1. Выбор грида: собственный canvas-грид ✅

| Критерий (из ARCHITECTURE §3) | Glide Data Grid (MIT) | Собственный canvas-грид |
|---|---|---|
| 60 fps @ 100k×30 | ✅ канвас-рендер | ✅ **подтверждено замером**: кадр рисует только видимое окно (~20×12 ячеек), avg draw 0.5–2 мс в e2e-замере (бюджет 16 мс), стресс-тест `tests/grid.spec.ts` гоняет прокрутку вглубь 100k строк |
| Кастомные жесты ПКМ/Alt/Ctrl | ⚠️ частично: свои обработчики есть, но модель выделения GDG — **один прямоугольный диапазон**; Ctrl-несмежные массивы (Ф5 — ядро ТЗ) публичным API не поддерживаются | ✅ полный контроль: несмежные области, Alt-лассо, ПКМ под будущий фильтр — всё уже в ядре `core/selection` |
| Кириллица/IME | ⚠️ канвас-редактор требует своего IME-оверлея у GDG | ✅ **DOM-input поверх канваса** — IME и кириллица работают нативно браузером |
| Бандл | ~200+ КБ (сам грид + lodash-зависимости) | 0 КБ зависимок; весь бандл приложения 57 КБ gzip (React+zustand+lucide включены) |
| Трудоёмкость доработки | высокая на «революционный UX» (Ф3–Ф5 завязаны на нестандартные выделения) | средняя: ядро (модель+рендер+жесты) собрано в рамках Этапа 1 |

**Решение: собственный canvas-грид.** Решающий аргумент — Ф5: Ctrl-несмежные
массивы как основа Σ/метрик не вписываются в модель выделения GDG без форка.
Архитектурное правило «менять гридер, не трогая логику» сохранено: вся логика
в `core/` (чистый TS, юнит-тесты), грид — тонкий слой `grid/` поверх стора.

## 2. Undo: delta-стек вместо zundo (уточнение стека)

План предполагал zundo (снимки состояния). Замер показал: снимок листа 100k
ячеек — полная копия Map на каждый шаг истории (~сотни МБ на 50 шагов).
**Решение: собственный delta-стек `core/history`** — запись хранит только
изменённые ячейки («было → стало»), шаг весит байты. ARCHITECTURE §2 обновлён.

## 3. Механика быстрой суммы: Alt остаётся, липкий Σ — запасной ✅

Alt+перетаскивание реализовано (Ф4): оранжевое лассо + живая сумма у курсора
без единого клика. Проверка матрицей:

| Платформа | Результат |
|---|---|
| Windows 10/11, Chromium | ✅ работает: preventDefault на pointerdown снимает перехват меню; подтверждено автотестом `Alt+перетаскивание: живая сумма у курсора` (Playwright, Chromium) |
| macOS / Linux | 🕒 ручная проверка отложена до матрицы платформ (Этап 5, пункт 5.4): риск — Alt+drag может двигать окно в macOS-окнах; митигция готова |

**Решение (КТ-2):** основная механика — **Alt+перетаскивание** (подтверждена на
Windows автотестом); «липкий Σ-режим» (включил кнопку Σ — следующее выделение
сразу показывает сумму) остаётся спроектированным запасным путём и войдёт в
Этап 3 (3.5) как дубль для платформ, где ОС перехватывает Alt.

## 4. Артефакты спика в коде

- `src/grid/geometry.ts` — чистая математика виртуализации (юнит-тесты)
- `src/grid/renderer.ts` — кадр канваса: только видимое окно + sticky-шапки
- `src/grid/GridCanvas.tsx` — жесты, клавиатура, DOM-редактор (IME), Alt-лассо
- `src/core/{sheet,selection,history,store}.ts` — модель без DOM (40 юнит-тестов)
- `tests/grid.spec.ts` — 8 e2e: выделение/правки/undo/Alt/стресс 100k×30

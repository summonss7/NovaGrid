# NovaGrid — Отчёт о производительности (Этап 6.1)

Дата: 2026-10-09 · Замеры: Playwright + Chromium (dev-сервер, продовый JIT),
медианы повторов на стресс-листе **100 000 строк × 30 колонок** (стресс-режим
`?stress=100000`, эквивалент `stress-100k.csv` со стартового экрана).
Воспроизведение: `npm run dev` + `node scripts/profile-stress.mjs`.

## Найденные узкие места и исправления

### 1. `selectionMetrics` материализовал массивы координат — 340 мс → 45 мс

Выделение колонки на 100k строило два массива по 100k элементов (`rows[]`,
`cols[]`), массив значений и три лишних прохода (sum → average → min/max).
Статус-бар к тому же подписывался на метрики **трижды** — каждый selector
zustand пересчитывал агрегат по всему выделению на каждое изменение стора.

Исправление (src/core/store.ts): однопроходная потоковая агрегация без
промежуточных массивов (`MetricsAgg` + `aggCell`), StatusBar считает метрики
один раз на изменение (`useMemo` по `sheet/selection/filters`). Выигрыш 7.6×;
drag-выделение колонки больше не блокирует поток на треть секунды.

### 2. `valuePasses` — линейный скан значений фильтра — 83 мс → 30 мс (и убран квадратичный рост)

`values.includes(raw)` по каждой строке: фильтр с сотней галочек меню колонки
платил O(строк × значений). Теперь `visibleRowsOf` готовит `Set` значений для
фильтров с >8 значениями: O(строк) независимо от ширины фильтра.

### 3. Диагностика попутно: `rafRef` после StrictMode-ремонта (Этап 5, блокировал карточку 009)

cleanup монт-эффекта грида отменял запланированный rAF без обнуления `rafRef` —
после дев-перемонтирования `scheduleDraw` навсегда уходил в ранний return и
канвас не перерисовывался при скролле. Исправлено обнулением после
`cancelAnimationFrame` (7e0f7eb); стресс-e2e «кадр 60 fps» снова зелёный.

## Что осталось в норме без изменений

- Кадр рендера грида: рисуется только видимое окно ~20×12 ячеек — e2e-бюджет
  выполняется с запасом (avg < 1 мс против бюджета 16 мс).
- Раскладка строк (фильтры) кэшируется по ссылке `(sheet, filters)` — кадр
  скролла платит O(1).
- Пересчёт формул инкрементальный (WeakMap по листу, зависимости по
  прямоугольникам) — правка ячейки с живым SUM по всей колонке ~58 мс.
- IO в воркере — интерфейс не замирает на разборе файлов (стресс 100k
  открывается и читается на глубину, e2e).
